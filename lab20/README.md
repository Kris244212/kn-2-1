# Лабораторна робота №20  
## Тема: SRP – декомпозиція OrderProcessor

### Мета роботи
Застосувати принцип єдиної відповідальності (Single Responsibility Principle, SRP) для
рефакторингу класу `OrderProcessor` шляхом його декомпозиції на менші, більш
спеціалізовані компоненти.

---

## Опис проєкту
Проєкт є консольним застосунком на C#, який демонструє:
- початкову реалізацію класу `OrderProcessor`, що порушує SRP;
- рефакторинг коду з використанням інтерфейсів;
- застосування Dependency Injection;
- обробку валідних та невалідних замовлень.

Кожен клас після рефакторингу відповідає лише за одну зону відповідальності.

## Основні компоненти

### Order
Модель замовлення, яка містить інформацію про клієнта, суму замовлення та його статус.

### IOrderValidator
Інтерфейс для перевірки валідності замовлення.

### IOrderRepository
Інтерфейс для збереження та отримання замовлень.

### IEmailService
Інтерфейс для відправки email-повідомлень клієнтам.

### OrderService
Головний сервіс, який координує роботу інших компонентів і реалізує бізнес-логіку
обробки замовлень з використанням Dependency Injection.



## Демонстрація роботи
У методі `Main` створюються:
- валідне замовлення (коректна сума);
- невалідне замовлення (від’ємна сума).

Результати обробки виводяться в консоль.



## Використані принципи та підходи
- **Single Responsibility Principle (SRP)**
- **Dependency Injection**
- **Інтерфейси та слабке зв’язування компонентів**
- **Чиста архітектура та читабельний код**
